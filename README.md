# Pexels Photo Search
Pexels APIを利用して、写真検索と閲覧ができるAndroidアプリケーションです。

## 採用したアーキテクチャについて
Clean Architectureを採用し、UI層ではMVIパターンを使用しました。

アプリケーションを以下のように分けています：
- `data` - API通信、DTO、Repositoryの実装
- `domain` - ドメインモデル、Repository Interface、UseCase
- `ui` - Compose画面、ViewModel、画面の状態とイベント
- `navigation` - 画面間の遷移
- `di` - DI関連の実装

MVIを採用した理由は、画面の状態を一つにまとめることで、読み込み中、成功、エラー、検索などの状態を分かりやすく管理できるためです。

また、アプリケーションの規模が小さいため、マルチモジュール構成にはせず、パッケージ単位でデータ層・ドメイン層・UI層を分割しました。

### DI
DIにはHiltを使用しました。
HiltはAndroidやViewModelのライフサイクルとの連携がしやすいため採用しました。

### 他の使用技術
Android開発で一般的に利用されているライブラリを使用しました。

## ユニットテスト
ViewModel、MainScreen、データ層のMapperの一部にテストを実装しました。

アプリケーションの中で重要な処理や状態の変化を確認できる箇所を中心にテストしました：
- MainScreenには主なUI要素が含まれているため、画面の状態によって正しいUI要素が表示されることを確認しました。
- MainViewModelには検索、次のページの取得、データ取得などの処理があるため、成功時とエラー時に状態が正しく更新されることを確認しました。
- Mapperについては、APIのレスポンスが正しくアプリ内のモデルに変換されることを確認しました。

## 時間の制約で、意図的に実装しなかったこと
時間の制約と課題の範囲を考えて、以下については実装していませんでした：
- UIの細かい作り込み
- Paging 3を利用したページネーション
- APIエラーなどを含む、より詳細なエラー処理
- 写真選択画面での画像の拡大・縮小などの操作
- より広い範囲のユニットテスト（特にページネーションや検索処理）

#### 大事なポイント
また、APIキーやAPI URLについては、今回の課題ではリポジトリーからすぐにアプリを実行して確認できるようにするため、Build Fileに記載し、リポジトリーに含めています。
実務のプロジェクトでは、APIキーなどの機密情報を公開リポジトリーに含めず、適切な方法で管理します。
